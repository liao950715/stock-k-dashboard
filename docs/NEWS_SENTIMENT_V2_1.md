## 2. 公式與參數（全部集中在 `news_sentiment.PARAMS`）

* 五級情緒：強烈偏空 −1、偏空 −0.5、中性 0、偏多 +0.5、強烈偏多 +1
* 重要性 I：等級 1 = 1.0、2 = 1.5、3 = 2.0、4 = 3.0（事件類型與等級分開儲存）
* 相關性：R < 0.3 排除；0.3 ≤ R < 0.7 → R′ = 0.5；R ≥ 0.7 → R′ = 1.0
* 時間衰減：T = 2^(−t/H)，H = 6 / 3 / 2 / 1 交易日（等級 4 / 3 / 2 / 1），t > 3H 排除
* 權重：W = I × R′ × T × U（P0：U = 1）
* 集中度：K_incl ≥ 3 時，單一事件權重 ≤ 40%（封閉解，依序嘗試被壓的事件數 m，一定終止；不可行時回報）；K_incl < 3 不套用，只靠收縮
* NSI_raw = Σ(W·s)/ΣW；NSI_shrunk = Σ(W·s)/(ΣW + W₀)，W₀ = 2；顯示 100 × NSI_shrunk
* n_eff = (ΣW)²/Σ(W²)；A = Σ(W|s|)/ΣW；Ω = 1 − |Σ(W·s)|/Σ(W|s|)（分母為 0 → 顯示「無明顯方向性新聞」）
* 五級標籤：≥ +40、≥ +15、(−15, +15)、> −40、≤ −40；UI 顯示標籤另有 5 分遲滯緩衝（正式 NSI 與正式標籤不受影響）
* 動能：M₅ = NSI_d − NSI_{d−5}；±10 判斷改善 / 惡化；兩快照都要有效、穩健程度 ≥ 中、公式版本相同
* 敏感度：正式權重、等權重、不使用時間衰減、替代重要性（1 / 1.25 / 1.5 / 2）；同一標籤，或差距 < 15 且沒有正負翻轉 → 一致
* 穩健程度：高 = K ≥ 5、n_eff ≥ 3、敏感度一致、無嚴重矛盾；中 = K ≥ 3、n_eff ≥ 2、矛盾來源占比 < 40%；其餘為低

統計定位：NSI 是實用的收縮估計（可視為常態先驗下的收縮均值），離散分數與事件不獨立都不符合嚴格假設，**不輸出信賴區間，也不宣稱有預測能力**。所有門檻都是待驗證的初始參數。

## 3. 時間尺度

* 統一單位：有效交易日間隔 t（整數）
* 新聞可用交易日：交易日收盤前（盤前、盤中）發布 → 當天；收盤後、週末、假日 → 下一個交易日
* 分析交易日：交易日開盤後 → 當天；其餘 → 前一個交易日
* t = 可用交易日到分析交易日之間的交易日數（不足時為 0）
* 交易日曆：過去日期以大盤指數（^TWII / ^GSPC）實際日 K 為準；未來日期用證交所休市日 API ＋ 週一至週五
* 所有時間轉成交易所時區（台股 UTC+8、美股紐約時間）；保存原始發布時間、第一次取得時間、對應交易日與 t

## 4. 事件、版本與確認狀態

* 同事件：同股票、48 小時內、標題相似度 ≥ 0.80、事件等級相同、期別字樣（季度 / 月 / 年 / 日期）相同
* 版本：標題含「更正 / 澄清 / 否認 / 撤回」且與舊事件相似 ≥ 0.5（7 日內）→ 舊事件升版，舊版新聞移入 superseded，不再計票，history 保留每個版本
* 確認狀態：官方確認（來自證交所 / 櫃買中心重大訊息）、多個獨立來源支持、單一來源、未證實（傳聞）、來源互相矛盾、已否認、已更正或取代
* 獨立來源：同一媒體只算一個；不同媒體但標題相似度 ≥ 0.95 視為轉載，只算一個
* 計分資格：相關性不足、已否認、已撤回、未證實傳聞不納入 NSI（傳聞只進警示通道）

## 5. 資料庫與四層快取（SQLite，`data/news_history.sqlite`）

| 層 | 資料表 | 快取鍵 |
|---|---|---|
| L1 原始新聞 | `news_raw` | news_id + content_hash（保留第一次取得時間） |
| L2 分類 | `classifications` | news_id + content_hash + model + model_version + prompt_version |
| L3 計算 | `quant_cache`、`events`、`snapshots`、`fetch_log` | 股票 + 分析交易日 + 公式 / 參數版本 + 事件版本集合 |
| L4 摘要 | `summaries` | 股票 + 事件版本集合 + 快照 ID + 模型版本 + 摘要 prompt 版本（另存指紋、生成時間、資料截點、引用 event_id） |

`fetch_log` 每天每種狀態一筆，用來區分「查詢成功但沒有新事件」、「查詢失敗」、「當天沒有執行」。

## 6. AI 摘要觸發機制

* 自動顯示快取摘要；摘要指紋（重大事件與狀態、警示、顯示標籤、模型與 prompt 版本）改變 → 重新生成
* 摘要超過 24 小時且有新事件 → 重新生成；只是時間衰減造成的 NSI 小變化 → 不重算
* 手動「重新分析」：同一 session 與同一股票各 60 秒冷卻，記錄在 `manual_runs`
* 同一股票同時只允許一個生成（鎖），其他請求先顯示快取
* AI 只解釋程式提供的數字；輸出用 JSON schema，程式端驗證 event_id 與數字，不通過視為失敗
* 失敗：有舊摘要 → 顯示並標示「已過期」；沒有 → 顯示規則式摘要並標示「非 AI 生成」
* Provider（依 Streamlit Secrets 自動選擇，OpenRouter 優先）：
  * `OPENROUTER_API_KEY` → OpenRouter `anthropic/claude-opus-5.5`（HTTP API、structured outputs JSON schema、`reasoning.effort = low`）
  * `ANTHROPIC_API_KEY` → Anthropic 官方 API `claude-opus-5-5`（`effort: low`，啟用 server-side fallback）
* 啟用方式：Streamlit Cloud → App settings → Secrets 加入其中一個金鑰（會產生 API 費用，每次摘要約 0.02～0.04 美元）
* 錯誤對應：401 金鑰無效、402 餘額不足、429 太頻繁、逾時 / 連線失敗 → 都視為失敗並回退，不偽造摘要

## 9. 已知限制

* 情緒、事件類型、相關性是**規則式關鍵字判斷**，未經準確率驗證；只看標題（新聞來源不提供內文）
* 去重與版本判斷只能比較標題與期別字樣，無法比對內文或財務數字
* Google 新聞 RSS 每次只回傳最新一批結果；較舊的新聞只有在曾經被抓到時才會保存在 L1
* 證交所 / 櫃買中心重大訊息 API 只提供當天公告
* **Streamlit Community Cloud 重新部署或重啟時會清空 SQLite**，雲端的歷史快照只從最近一次部署後開始累積；而且只有在有人打開頁面時才會記錄快照（沒有排程）
* 美股沒有休市日 API，未來日期只用週一至週五判斷（過去日期仍以實際行情為準）
